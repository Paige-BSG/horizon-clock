# Security and privacy

HORIZON has no account system, telemetry or analytics. Weather is enabled by default and uses the system geolocation API, subject to system/browser location policy. High accuracy is disabled; coordinates are rounded to two decimal places before local storage or transmission to Open-Meteo. HORIZON does not select an unrelated city when location fails. Users can disable weather or select a manual city. Existing saved off choices remain off. Network providers can still see the requesting IP address. Checking for updates contacts GitHub only when the user presses the button. Online scenery is separately off until enabled. It contacts Wikimedia Commons and its thumbnail CDN once per day while visible (or on explicit retry), without accounts, API keys, cookies, referrers or personal photos. Failed updates retry after an hour; attempts are at least a minute apart. Requests identify the app with Api-User-Agent. Providers can see the requesting IP address.

Preferences, a rounded last-known weather location (valid for 24 hours), recent weather, downloaded online backgrounds and imported photo copies are stored on the device. Photos are never sent to the weather provider or GitHub. The importer accepts raster JPG/PNG/WebP after file-signature validation, applies file/pixel/library limits, re-encodes copies without original EXIF metadata and creates small thumbnails. Removing an entry deletes the library copy only, never its original file. Clearing the app/browser data can remove the library; settings JSON backups do not contain photos. The desktop frontend is embedded in the application. The development server listens on `127.0.0.1` and only serves frontend files; it is not a production or public hosting server.

Native commands are limited to the local application window and specific fullscreen, autostart, awake, photo-source, typed NetEase playback and scoped waveform operations. Photo-source opening allows only HTTPS photo/license pages on the named providers; it opens the default browser through the Tauri opener plugin. No arbitrary shell execution or filesystem commands are exposed. Keep-awake inhibitors are scoped to the application lifetime. HORIZON does not disable authentication, change global sleep policies, or install itself at login without a user's choice.

NetEase music uses a typed native account/playback command, not web media loading; the frontend media CSP is disabled. Only loaded account-playlist track IDs may be played. Credentials remain in the system keyring and signed stream URLs remain native. The task-owned mpv child receives its URL through private IPC, never argv. Account restore does not autoplay; closing the controls preserves intentional playback, while window close or page-load invalidation stops it. No arbitrary API/stream URL, download or recording is exposed. See [music](docs/MUSIC.md).

Online responses are treated as untrusted data: only known Creative Commons/public-domain license labels and trusted JPEG/source hosts are accepted; attribution is rendered as text. Metadata is capped at 512 KiB per request, each image download at 4 MiB, the batch at 24 images plus up to two currently selected older images, and cache storage at 96 MiB. At most three images download concurrently. Requests time out after 45 seconds. Catalog replacement commits atomically; failures retain the existing cache. Turning online scenery off aborts requests and stops future checks while retaining cached images. Settings backups omit network consent and do not contain online photo bytes.

Location coordinates are not included in settings backups. Location failures may display a labeled last-position weather cache, but do not trigger weather requests using that position. Location permission is granted within the native webview only for the local main clock page; external pages receive platform-default permission handling.

Settings imports validate a versioned schema, accept known fields only, cap input size, and preserve this device's network consent and power choices. Updates currently check release metadata only: they do not download or execute code. Signed application updates are a future release gate; never place signing keys in this repository.

Report non-sensitive defects through GitHub Issues. For a vulnerability, use GitHub's private vulnerability reporting if available, or contact the maintainer through their GitHub profile before disclosing technical exploit details. Do not publish credentials or private data in an issue.

This is an alpha project. The 1.0 security and reliability acceptance gates are recorded in [ROADMAP.md](ROADMAP.md).

On Omarchy, optional waveform metering is restricted to exactly one PulseAudio/PipeWire playback stream whose process ID belongs to the app or a verified descendant. Fixed local list queries are bounded in time and output size. The monitor source must match that stream's sink; `parec` receives a mandatory explicit monitor source and stream index, with no default-source fallback. Frontend callers cannot choose a process, device or stream. PCM remains in memory and is discarded after frequency/energy computation; only93derived numeric values cross IPC, including64downsampled waveform points. Capture stops when not playing, muted, closed, hidden, motion-paused or the window exits. Missing/ambiguous ownership or stale measurements yield no data. No system routing, microphone setting or global volume is changed.
