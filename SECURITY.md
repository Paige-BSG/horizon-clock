# Security and privacy

HORIZON has no account system, telemetry or analytics. Weather is off until enabled. If enabled, it sends only the selected city's rounded center coordinates to Open-Meteo; it never reads GPS. Network providers can still see the requesting IP address. Checking for updates contacts GitHub only when the user presses the button. Online scenery is separately off until enabled. It contacts Wikimedia Commons and its thumbnail CDN once per day while visible (or on explicit retry), without accounts, API keys, cookies, referrers or personal photos. Failed updates retry after an hour; attempts are at least a minute apart. Requests identify the app with Api-User-Agent. Providers can see the requesting IP address.

Preferences, recent weather, downloaded online backgrounds and imported photo copies are stored on the device. Photos are never sent to the weather provider or GitHub. The importer accepts raster JPG/PNG/WebP after file-signature validation, applies file/pixel/library limits, re-encodes copies without original EXIF metadata and creates small thumbnails. Removing an entry deletes the library copy only, never its original file. Clearing the app/browser data can remove the library; settings JSON backups do not contain photos. The desktop frontend is embedded in the application. The development server listens on `127.0.0.1` and only serves frontend files; it is not a production or public hosting server.

Native commands are limited to the local application window and specific fullscreen, autostart, awake, photo-source and radio-source operations. Photo-source opening allows only HTTPS photo/license pages on the named providers; it opens the default browser through the Tauri opener plugin. No arbitrary shell execution or filesystem commands are exposed. Keep-awake inhibitors are scoped to the application lifetime. HORIZON does not disable authentication, change global sleep policies, or install itself at login without a user's choice.

Network radio is opt-in on each application launch: opening the bar or choosing a station makes no network request. An explicit Play action creates a single HTML audio element for a bundled HTTPS Radio Paradise stream. Media requests use the no-referrer document policy; no account is needed. The system webview manages stream transport and any provider service cookies; HORIZON does not read or import them. The media CSP is limited to the provider's HTTPS subdomains. No arbitrary stream URL, audio download, recording, artwork or metadata API is exposed. Stop/unload releases the media source and cancels retries; closing the controls preserves intentional playback. Timeouts and a three-retry budget bound failures. Only channel ID and clamped volume are stored locally, never playback intent or audio. A fixed local GStreamer inspection runs off the UI thread with a three-second deadline before enabling desktop playback; it takes no frontend arguments and installs nothing. A fixed native source command opens the provider's official stream-links page without accepting a URL argument. See [network radio](docs/MUSIC.md).

Online responses are treated as untrusted data: only known Creative Commons/public-domain license labels and trusted JPEG/source hosts are accepted; attribution is rendered as text. Metadata is capped at 512 KiB per request, each image download at 4 MiB, the batch at six images plus up to two currently selected older images, and cache storage at 32 MiB. Requests time out after 45 seconds. Catalog replacement commits atomically; failures retain the existing cache. Turning online scenery off aborts requests and stops future checks while retaining cached images. Settings backups omit network consent and do not contain online photo bytes.

Settings imports validate a versioned schema, accept known fields only, cap input size, and preserve this device's network consent and power choices. Updates currently check release metadata only: they do not download or execute code. Signed application updates are a future release gate; never place signing keys in this repository.

Report non-sensitive defects through GitHub Issues. For a vulnerability, use GitHub's private vulnerability reporting if available, or contact the maintainer through their GitHub profile before disclosing technical exploit details. Do not publish credentials or private data in an issue.

This is an alpha project. The 1.0 security and reliability acceptance gates are recorded in [ROADMAP.md](ROADMAP.md).
