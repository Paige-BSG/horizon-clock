# Architecture

## Frontend

Vanilla HTML, CSS and ECMAScript modules preserve the accepted visual design without introducing a UI framework. `app.js` owns clock rendering and interaction. `lib/backgrounds.js` owns profile previews, image transitions, playlists and the album interface; `lib/photos.js` owns local IndexedDB storage and image normalization. `lib/settings.js` validates and migrates preferences; `lib/night.js` owns local-time night scheduling; `lib/location.js` obtains and rounds system coordinates; `lib/weather.js` parses provider data and validates cache. `lib/product.js` connects weather, settings backup and release metadata checking to the interface.

`lib/china-calendar.js` contains sourced annual mainland holiday overrides. `lib/alarm-model.js` validates alarms and computes local-time occurrences; `lib/alarms.js` owns alarm settings and ringing dialogs. The desktop `alarm` controller runs its own clock thread over 35 days of supplied occurrences, deduplicates fired timestamps and manages a separate mpv child for the embedded offline WAV. Anonymous IPC closure ends that child when the app dies; normal stop/close kills and reaps it. No new production dependency or system scheduler is used. Calendar coverage and operating limits are documented in [ALARMS.md](ALARMS.md).

`scripts/build.mjs` copies a fixed frontend file set into `dist/`. No source server, package manager or Node runtime is required by the installed app. Assets are local and embedded in the desktop distribution. `scripts/serve.mjs` is a loopback-only development server with an explicit file allowlist.

Background transitions retain an opaque outgoing image under a decoded incoming image, with the contrast mask above both. Only the incoming image fades; simultaneous fade-out/fade-in would expose the dark backdrop. Reuse of the two image layers waits for transition completion (with a bounded fallback), and superseded requests are discarded before committing. Reduced-motion settings skip the fade.

## Desktop

Tauri 2 embeds the frontend in the platform webview. Five narrow commands expose fullscreen state/control, autostart state/control and awake control. Autostart uses the maintained Tauri plugin and changes only after user interaction. Native awake system-service requests run on blocking workers. Enable/disable requests are serialized; a window-close flag rejects late acquisitions. Linux D-Bus method calls have a five-second deadline.

Native Wayland sessions use `zwp_idle_inhibit_manager_v1` on the clock window’s existing surface, plus a systemd-logind `idle` inhibitor. A separate event queue borrows GTK’s connection without owning its display or surface. Only Wayland acquisition and display-inhibitor cleanup run on the GTK thread so borrowed handles cannot race window destruction; logind and ScreenSaver D-Bus acquisition/release run on workers. Non-Wayland Linux sessions retain the ScreenSaver D-Bus backend. Both display and logind requests must succeed; partial failure releases the first inhibitor. Disabling or closing the window releases both. Other development platforms use `keepawake`. The application does not change global power policies or block explicit manual suspend. A hidden/unmapped Wayland surface follows compositor visibility rules.

The frontend has no shell or arbitrary filesystem API. A restricted content policy allows local assets, native IPC and the two optional network hosts. Browser previews use the Screen Wake Lock API instead of native controls.

## State and networking

- `horizon-display-v1`: validated preferences, keeping compatibility with the design prototype. v0.2 adds independent day/night background, dimming and information-brightness fields. JSON backups use schema version 2 and accept older version-1 files.
- `horizon-photos-v1`: device-local IndexedDB library holding normalized JPEG copies, small thumbnails, enabled state and framing coordinates. File imports are sequential, deduplicated by SHA-256 of the source and capped at 24 photos / 64 MiB total; each input is limited to 20 MiB and 40 megapixels. Full copies are reduced to a maximum 2560-pixel edge. Canvas re-encoding strips the original metadata. No original path or raw file is retained. Settings backups contain references, not photo files. Library transactions enforce capacity across windows.
- `horizon-weather-v1:<place>`: per-city or rounded-coordinate weather snapshots, rejected after 24 hours or if malformed. Fetching occurs every 15 minutes while visible, with a 10-second timeout. Hidden pages stop periodic weather and scene work; resume checks the cache age.
- Weather defaults on, using system geolocation with high accuracy disabled. Coordinates are rounded to two decimal places before persistence or requests. Location lookup has an independent 10-second deadline and is canceled when disabled, replaced or hidden. Last-position cache is labeled when current location is unavailable; no IP-location or unrelated-city fallback is used. Manual city-center selection remains available. Native geolocation permission is scoped to the local main webview. There are no accounts or telemetry.
- Imports preserve the receiving device's network consent and awake state; native autostart is managed independently. Exports are JSON with an app identifier and schema version.
- Update checking is user-triggered HTTPS metadata retrieval from the fixed GitHub repository. No downloaded code is executed. Update installation/signing remains a release milestone.

## Build and maintenance choices

Production dependencies are confined to desktop integration: Tauri, its autostart plugin, zbus and Wayland protocol bindings on Linux, and keepawake on other platforms. Wayland bindings are necessary because Omarchy 4.5 has no ScreenSaver D-Bus service. The optional `native-qa` feature adds an embedded loopback-only WebDriver server for testing; it is absent from normal builds. Their cost is the native Rust/GTK/webview build toolchain and OS-specific testing. Development uses Node built-ins, Playwright and Prettier. Lockfiles pin dependencies. Public CI uses standard Ubuntu runners and does not upload artifacts or enable build caches.

Sources: [Tauri prerequisites](https://tauri.app/start/prerequisites/), [autostart](https://tauri.app/plugin/autostart/), [Linux distribution](https://tauri.app/distribute/), [Open-Meteo API](https://open-meteo.com/en/docs), [Omarchy idle behavior](https://omarchy.org/manual/toggles-idle-screensaver/).

## Online scenery

`lib/scenes.js` supplies the 21 bundled backgrounds and their individual credits. `gallery-model.js` validates Commons category/image metadata, URLs, licenses and bounded response bodies. `online-gallery.js` performs consent-gated daily checks, downloads and normalizes up to 24 JPEGs, and atomically replaces the separate `horizon-online-v1` IndexedDB snapshot. Up to two day/night-selected older scenes remain available. Personal-photo storage is separate and unchanged. Newest-first category IDs are retained independently of imageinfo page-ID ordering. Cache identity includes the Commons image revision SHA1; object URLs are reclaimed after crossfades.

The desktop adds the official `tauri-plugin-opener` only for user-clicked source/license pages. Frontend links invoke an HTTPS/host/path validated Rust command; arbitrary shell/filesystem opening is not exposed. CSP connect-src permits Commons metadata and thumbnail CDNs. Photos are displayed from bundled files or cached blob URLs. No image-provider key, remote configuration server or new backend is required.

## Music layout and measured waveform

`lib/music.js` keeps the4:6player/clock composition and switches only the left panel between listening and playlist browsing. Transport and volume remain fixed below both views; account/QR controls live in App settings. The first music/account interaction restores the session without autoplay. Collapsing preserves playback; Escape closes the library before collapsing the panel. Settings close cancels a pending QR login.

`lib/music-scene.js` draws64measured waveform points, flat when idle, paused or muted. Idle views do not continuously render. Frames are capped around30fps; the motion preference is independent of playback. Missing canvas leaves controls usable. `lib/music-meter.js` uses the fixed native `set_music_meter`/`music_audio_levels` commands. Browser preview has no playback or Web Audio fallback.

`music_meter.rs` selects exactly one app-owned descendant playback stream and its exact sink monitor, then starts `parec` with both monitor source and stream index. No frontend device/process arguments or microphone/global fallback exist. Bounded discovery fails closed. Samples remain in memory; only93derived values, including64signed waveform points, cross IPC and expire after500ms. Capture stops on mute, library/collapsed/hidden view, motion pause or close. Other native platforms return unavailable. Logical viewport variables retain correct sizing under native font scaling.

## Native NetEase source

`lib/netease.js` renders QR login, the signed-in account's playlists and paginated tracks, and playback controls. `lib/music.js` coordinates the listening, library and account views. Session restore never starts playback. A generation counter prevents late UI responses from replacing a newer session. User operations received during polling execute afterward in click order; transport intent is resolved against the latest playback state. Polls do not display a busy transition. Browsing and playback retain separate loaded collections. Browsing another playlist cannot replace playback history, current-list contents or continuation; only explicit song selection or starting personal FM selects a new playback collection. Queue pagination and recommendation continuation update that collection independently of the browser.

`src-tauri/src/netease.rs` exposes one typed command with a fixed action enum. `netease/engine.rs` owns a serialized account adapter, bounded API requests, transient QR data and a separate owned-player lock. Account/playlist IDs are derived from the restored account. Track IDs are restricted to the loaded account playlist or authenticated personal-FM recommendation queue. Recommendation metadata is sanitized through the same track model; no URL is returned to the frontend. The frontend receives text metadata, QR image and playback state, never credentials or stream URLs. Session storage is the system keyring without a plaintext fallback. The existing authorized probe credential is read in place under its original HORIZON namespace; logout explicitly removes only this local entry.

The pinned ncm-api-rs SDK runs in library mode with HTTP/2 enabled, no HTTP server and no alternate login/IP/proxy fallback. Standard-quality `song_url` responses must have a permitted HTTPS NetEase CDN address and no trial flag. Playback uses a task-owned mpv child with an anonymous Unix socket pair passed as stdin (`--input-ipc-client=fd://0`), null process output and no URL or cookie in argv. No socket file or temporary directory is created. mpv exits when the app closes the connection, including process termination or a crash; its lifetime is independent of the thread that spawned it. Linux selects PulseAudio-compatible output. Duration is checked against track metadata; only an actual `end-file/eof` event with matching elapsed time counts as normal completion and allows automatic next-track playback. `netease/player.rs` owns serialized player controls and a 250-ms native progress monitor, independent of frontend polling and account requests. Status reads use its in-memory snapshot. Stream-duration mismatch stops the owned child even when the frontend is not polling. Closing shuts down IPC before joining the monitor and reaping the child. Errors remain visible and do not automatically skip unavailable tracks.

The existing native meter selects the uniquely owned child stream and its exact monitor, for the measured-waveform renderer. Window close kills and waits for the owned player. Page-load invalidation stops playback and rejects late play requests from the previous page. Native dependencies and upstream notices are included in the desktop source and package inputs; the external mpv runtime is needed only for music playback.

`lib/music-queue.js` owns local playback-mode validation, non-repeating shuffle cycles and bounded actual-play history. Sequential/loop playback fetches the next page at a loaded-page boundary; shuffle fills the entire selected playlist before drawing. Single-repeat applies to validated EOF, not manual Next. Only the mode enum is persisted under `horizon-music-v1`. `Fm { append }` requests the pinned SDK personal-FM API, deduplicates a bounded batch, retains100recent recommendations and uses the same signed-URL/trial validation and owned mpv path. The frontend serializes compound fetch/play operations; an exhausted/failed recommendation response is not automatically retried or replaced by another source.

The player separates a flexible `.music-content` region (listening or library) from a fixed `.music-console`. All action buttons except individual song selection live in the console, including login entry, library navigation, personal FM, shuffle and pagination. The top-right toolbar music icon alone owns the visible expand/collapse control and updates its accessible label/expanded state. M/Escape shortcuts remain. The replaced internal source heading and close button are absent; browser tests assert action containment, toolbar toggling without restarting playback and compact-library bounds with all actions visible.
